## En bref

i3 est un gestionnaire de fenêtres en pavage (*tiling window manager*) : les
fenêtres se partagent l'écran automatiquement, tout se pilote au clavier. Cette
fiche est l'antisèche des raccourcis **par défaut**, plus le minimum de
configuration pour que la session soit vivable.

Toutes les combinaisons commencent par la **touche mod** (*modifier*), notée
`$mod` dans la configuration.

## Quelle touche est `$mod`

`i3-config-wizard` la demande au tout premier démarrage et écrit la réponse en
tête de `~/.config/i3/config` :

```sh
grep '^set \$mod' ~/.config/i3/config    # Mod1 = Alt, Mod4 = Super (touche Windows)
```

`Mod4` est le bon choix : `Alt` est déjà pris par la moitié des applications.
Pour en changer après coup, éditer cette ligne et recharger (`$mod+Shift+c`).

Dans les tableaux ci-dessous, `Mod` = cette touche.

## Fenêtres et focus

| Touches | Effet |
| --- | --- |
| `Mod+Entrée` | ouvre un terminal |
| `Mod+d` | lanceur d'applications (`dmenu`) |
| `Mod+Shift+q` | **ferme** la fenêtre active |
| `Mod+j` `Mod+k` `Mod+l` `Mod+;` | déplace le focus gauche / bas / haut / droite |
| `Mod+←` `Mod+↓` `Mod+↑` `Mod+→` | idem, aux flèches |
| `Mod+Shift+j/k/l/;` | **déplace la fenêtre** dans cette direction |
| `Mod+f` | plein écran (*fullscreen*), même touche pour en sortir |
| `Mod+Shift+espace` | bascule la fenêtre en flottant (*floating*) et retour |
| `Mod+espace` | passe le focus entre les fenêtres pavées et les flottantes |
| `Mod+clic gauche` | déplace une fenêtre flottante à la souris |
| `Mod+clic droit` | la redimensionne à la souris |

Les touches de focus sont `j k l ;` et **pas** `h j k l` comme dans Vim : `h`
est déjà pris par le découpage horizontal. C'est la première chose que tout le
monde reconfigure.

## Découper et disposer

| Touches | Effet |
| --- | --- |
| `Mod+h` | la **prochaine** fenêtre s'ouvrira à droite (découpe horizontale) |
| `Mod+v` | la prochaine fenêtre s'ouvrira en dessous (découpe verticale) |
| `Mod+e` | disposition en pavage : alterne horizontal / vertical |
| `Mod+s` | disposition empilée (*stacking*) : une seule visible, les titres listés |
| `Mod+w` | disposition en onglets (*tabbed*) |
| `Mod+a` | remonte le focus au conteneur parent (*focus parent*) |
| `Mod+r` | entre en mode redimensionnement — voir plus bas |

`Mod+h` et `Mod+v` ne découpent pas tout de suite : ils arment la direction de
la **prochaine** ouverture. Rien ne bouge à l'écran tant qu'on n'a pas lancé
quelque chose, ce n'est pas un raccourci qui a raté.

## Redimensionner

`Mod+r` entre dans un **mode** : les touches suivantes ne veulent plus dire la
même chose jusqu'à ce qu'on en sorte.

| Touches | Effet |
| --- | --- |
| `Mod+r` | entre en mode `resize` (le nom s'affiche dans la barre) |
| `j` `k` `l` `;` ou les flèches | élargit / rétrécit |
| `Entrée` ou `Échap` | sort du mode |

Tant que la barre affiche `resize`, taper du texte dans un terminal ne fait
rien : c'est le mode qui capte le clavier.

## Bureaux virtuels (*workspaces*)

| Touches | Effet |
| --- | --- |
| `Mod+1` … `Mod+0` | va au bureau 1 à 10 |
| `Mod+Shift+1` … `Mod+Shift+0` | **envoie** la fenêtre active sur ce bureau |

Un bureau vide disparaît tout seul dès qu'on le quitte : il n'y a rien à créer
ni à supprimer. `Mod+Shift+1` envoie la fenêtre **sans y aller** : pour la
suivre, enchaîner avec `Mod+1`.

Ce qui manque par défaut et se lie en trois lignes — le premier surtout, c'est
l'aller-retour entre les deux bureaux du moment :

```
bindsym $mod+Tab workspace back_and_forth       # revient au bureau precedent
bindsym $mod+Ctrl+l workspace next              # bureau suivant / precedent
bindsym $mod+Ctrl+h workspace prev
bindsym $mod+Ctrl+Shift+l move container to workspace next
```

Avec deux écrans, un bureau appartient à un écran : `Mod+1` bascule l'écran qui
héberge le bureau 1, pas forcément celui qu'on regarde.

```
bindsym $mod+Ctrl+Right focus output right                   # le focus change d'ecran
bindsym $mod+Ctrl+Shift+Right move container to output right # la fenetre change d'ecran
bindsym $mod+Shift+w move workspace to output right          # tout le bureau change d'ecran
```

## Session

| Touches | Effet |
| --- | --- |
| `Mod+Shift+c` | **recharge** la configuration (les fenêtres ne bougent pas) |
| `Mod+Shift+r` | **redémarre** i3 en place — la disposition est conservée |
| `Mod+Shift+e` | **quitte i3**, donc ferme la session (une confirmation s'affiche) |
| `Mod+Shift+moins` | envoie la fenêtre dans le tiroir (*scratchpad*) |
| `Mod+moins` | fait réapparaître la fenêtre du tiroir, puis la range |

`Mod+Shift+r` est le réflexe après avoir installé quelque chose qui touche à la
session ; il relit aussi la configuration, donc il remplace `Mod+Shift+c` en cas
de doute.

## Éteindre, redémarrer, verrouiller

**Il n'y a aucun raccourci par défaut pour éteindre**, et c'est volontaire : i3
gère des fenêtres, pas la machine. `Mod+Shift+e` ne fait que quitter i3.

En ligne de commande, c'est `systemctl` — mais le verbe n'est pas `shutdown` :

```sh
systemctl poweroff             # eteindre  (PAS `systemctl shutdown`, ce verbe n'existe pas)
systemctl reboot               # redemarrer
systemctl suspend              # mise en veille (RAM)
systemctl hibernate            # hibernation (disque)
shutdown -h now                # l'equivalent historique de poweroff
shutdown -h +10 "maintenance"  # dans 10 minutes, avec un message aux sessions ouvertes
shutdown -c                    # annule un arret programme
i3-msg exit                    # quitter i3 sans toucher a la machine
```

Aucun `sudo` n'est nécessaire depuis une session graphique locale : polkit
autorise l'utilisateur connecté. En SSH, `systemctl poweroff` demande le mot de
passe — ou refuse si une autre session est ouverte.

Le réflexe i3 est d'en faire un **mode**, pour n'avoir qu'un raccourci à retenir
au lieu de six. À coller dans la configuration :

```
set $syst  [l]ock  [e]xit  [s]uspend  [r]eboot  [Shift+p]oweroff
mode "$syst" {
    bindsym l exec --no-startup-id i3lock -c 000000, mode "default"
    bindsym e exec --no-startup-id i3-msg exit, mode "default"
    bindsym s exec --no-startup-id systemctl suspend, mode "default"
    bindsym r exec --no-startup-id systemctl reboot, mode "default"
    bindsym Shift+p exec --no-startup-id systemctl poweroff, mode "default"
    bindsym Escape mode "default"
    bindsym Return mode "default"
}
bindsym $mod+Shift+s mode "$syst"
```

`Mod+Shift+s`, puis une seule lettre. Le nom du mode s'affiche dans la barre, ce
qui sert d'aide-mémoire — d'où les crochets dans `set $syst`. La variante avec un
menu graphique est dans [rofi](rofi.md).

## Configuration

```sh
i3-config-wizard                          # regenere une config neuve (ecrase l'ancienne)
cp /etc/i3/config ~/.config/i3/config     # repartir du modele fourni par le paquet
i3 -C -c ~/.config/i3/config              # verifie la syntaxe SANS rien appliquer
```

Le fichier lu est `~/.config/i3/config` ; à défaut `~/.i3/config`, puis
`/etc/i3/config`. Une erreur de syntaxe au rechargement ouvre une barre rouge
(`i3-nagbar`) en haut de l'écran avec le numéro de ligne.

Quelques lignes qui manquent presque toujours :

```
exec_always --no-startup-id setxkbmap fr             # clavier AZERTY a chaque demarrage
exec_always --no-startup-id feh --bg-scale ~/fond.jpg # fond d'ecran
exec --no-startup-id nm-applet                        # icone reseau
exec --no-startup-id dunst                            # notifications
bindsym $mod+Shift+x exec i3lock -c 000000            # verrouiller l'ecran
bindsym Print exec --no-startup-id scrot ~/captures/%F-%T.png
bindsym XF86AudioRaiseVolume exec --no-startup-id pactl set-sink-volume @DEFAULT_SINK@ +5%
```

`exec` ne s'exécute qu'au démarrage d'i3, `exec_always` **aussi à chaque
rechargement**. Se tromper des deux, c'est soit une disposition clavier qui
retombe en QWERTY après un `Mod+Shift+c`, soit trois `nm-applet` empilés.

## Piloter i3 en ligne de commande

```sh
i3-msg reload                  # equivalent de Mod+Shift+c
i3-msg restart                 # equivalent de Mod+Shift+r
i3-msg -t get_workspaces       # la liste des bureaux, en JSON
i3-msg -t get_tree             # l'arbre complet des conteneurs
i3-msg 'workspace 3'           # basculer sur le bureau 3 depuis un script
i3-msg 'move container to workspace 2'
xev                            # affiche le keysym de la touche pressee (pour bindsym)
```

## Le modèle mental : un arbre de conteneurs

Une fenêtre n'est pas posée sur l'écran, elle est une feuille d'un arbre de
conteneurs (*containers*). Chaque découpe crée un conteneur parent qui contient
les fenêtres découpées. C'est ce qui explique les deux surprises du début :

- **une nouvelle fenêtre s'ouvre à côté de la fenêtre active**, dans le
  conteneur de celle-ci — pas « quelque part sur l'écran » ;
- **`Mod+s` ou `Mod+w` ne s'appliquent qu'au conteneur courant**, qui peut être
  imbriqué très profond. Si l'effet ne porte pas sur ce qu'on visait, remonter
  d'un cran avec `Mod+a` et recommencer.

`i3-msg -t get_tree` montre l'arbre réel quand on ne comprend plus la
disposition.

## Sur WSL

C'est la déception attendue : **i3 ne sert à rien sous WSLg**. WSLg affiche
chaque fenêtre Linux comme une fenêtre Windows ordinaire (Xwayland en mode
*rootless*) — il n'y a pas de bureau à carreler, et c'est Windows qui place les
fenêtres.

Le contournement qui marche : un serveur X **imbriqué**, i3 tourne alors dans
une fenêtre Windows unique.

```sh
sudo apt install i3 xserver-xephyr                     # Xephyr = serveur X dans une fenetre
Xephyr -br -ac -noreset -screen 1600x900 :1 &          # ouvre la fenetre, ecran :1
DISPLAY=:1 i3                                          # i3 gouverne CET ecran-la
DISPLAY=:1 xterm                                       # tout ce qu'on lance dedans lui appartient
```

Utile pour réviser les raccourcis, pas pour travailler : la fenêtre Xephyr est
un rectangle fixe, sans accélération ni intégration avec le reste du bureau.
Pour la vraie expérience, il faut une machine (ou une VM) qui démarre une
session X — c'est-à-dire la Debian.

## Pièges

- **`Mod+Shift+e` ferme la session**, et il est voisin de `Mod+Shift+q` qui ne
  ferme qu'une fenêtre. La confirmation `i3-nagbar` est la seule chose entre soi
  et la perte de tout ce qui est ouvert : la lire avant de valider.
- **Sur un clavier AZERTY, `Mod+1` ne change pas de bureau.** i3 lie un *keysym*,
  et le keysym `1` demande `Shift` en AZERTY : le raccourci par défaut répond
  donc à `Mod+Shift+&`. Remplacer les dix lignes `bindsym $mod+1 …` par les
  keysyms réels de la rangée du haut :

  ```
  bindsym $mod+ampersand workspace number 1
  bindsym $mod+eacute workspace number 2
  bindsym $mod+quotedbl workspace number 3
  bindsym $mod+apostrophe workspace number 4
  bindsym $mod+parenleft workspace number 5
  bindsym $mod+minus workspace number 6
  bindsym $mod+egrave workspace number 7
  bindsym $mod+underscore workspace number 8
  bindsym $mod+ccedilla workspace number 9
  bindsym $mod+agrave workspace number 10
  ```

  L'alternative indépendante de la disposition est `bindcode $mod+10` à
  `bindcode $mod+19`, qui vise la **position physique** de la touche. `xev` donne
  l'un comme l'autre.
- **i3 ne lance rien tout seul.** Pas de fond d'écran, pas d'icône réseau, pas de
  notifications, pas de verrouillage, pas de gestion du volume ni de la
  luminosité : ce n'est pas un environnement de bureau. Tout ce qui manque se
  déclare en `exec` dans la configuration — voir plus haut.
- **La disposition clavier retombe en QWERTY** à chaque session tant qu'aucun
  `setxkbmap fr` n'est déclaré. Et avec `exec` au lieu de `exec_always`, elle
  retombe au premier `Mod+Shift+c`.
- **Un écran branché à chaud n'est pas configuré.** Aucun démon ne s'en occupe :
  `xrandr --output HDMI-1 --auto --right-of eDP-1`, ou `arandr` pour le faire à
  la souris et enregistrer le script obtenu.
- **`Mod+h` ne fait rien de visible** : il arme la découpe de la prochaine
  fenêtre. Ne pas le retaper trois fois en croyant qu'il n'est pas passé.
- **La barre du bas est `i3status`, configurée ailleurs.** Pour la modifier :
  `cp /etc/i3status.conf ~/.config/i3status/config`, sinon toute édition est
  écrasée à la mise à jour du paquet.
- **Un rechargement ne relance pas les applications**, il ne relit que la
  configuration. Après avoir changé quelque chose qui touche à la session
  (barre, `exec_always`), c'est `Mod+Shift+r` qu'il faut.
- **Certaines fenêtres s'ouvrent flottantes** (boîtes de dialogue, GIMP) :
  c'est voulu, `Mod+Shift+espace` les repave.
